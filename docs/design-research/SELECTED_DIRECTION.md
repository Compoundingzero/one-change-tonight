# Selected direction: Inline First Question

Selected 2026-09-07. The homepage begins the assessment because the target user’s dominant need is to do something useful, not learn a product narrative. The first view includes a restrained mark, exact-situation headline, one-line promise, truthful local-only statement, concise medical boundary and the first question. This is an original editorial tool system, not a reskin of any reference.

## Interaction contract

- One question per screen; four to six large answers plus “I’m not sure.”
- No auto-advance, timer, points, streaks, confetti or false fixed total.
- Back preserves state; Continue is the only primary action.
- Selected state combines native radio, border, inset marker and surface change.
- Assessment header reduces to brand, exit/data controls and low-brightness access.
- Result order: pattern, clues, limitation, One Change Tonight, keep constant, observe tomorrow, Do Not Buy Yet, partner guidance, three nights, care reminder, sources.

## Visual system

The mark is one shifted vertical bar among stable bars: one variable changes while the system remains controlled. Warm paper and near-black green support mature editorial reading; teal marks action and selected state; sand distinguishes care and purchase restraint without alarm. Night mode is genuinely dark and avoids large animated or luminous regions. Rounded rectangles are used sparingly for task objects, not every paragraph.

System UI fonts avoid remote requests. Large headings use weight and line break rather than decorative type. The experiment card receives the strongest outline and surface; it is the equivalent of a creative tool’s output canvas while remaining complete HTML.

## Responsive behavior

At 320–430 px all controls stack in reading order, answer targets remain at least one control-height tall, partner columns become one column, and the question card uses nearly the viewport width without touching edges. At desktop the question stays bounded; added width becomes calm whitespace and later four-column framework explanation, not an inspector.

## Privacy, safety and search

No account, name or server submission is required. Personal answers do not enter URLs or analytics. Browser-storage limits and deletion remain visible. Pattern language is environmental and non-diagnostic; “What this does not mean” and care guidance remain visible. Static HTML carries purpose, boundaries, framework, evidence and direct search answers; only assessment/tracker state hydrates.

## Influence boundary

The direction borrows cross-site principles—action-first entry, central output, progressive disclosure, visible response and contextual privacy. It does not borrow a drop zone, canvas, mascot, code editor, palette, control layout, typography combination, copy, asset or branded motion from any reference.

## Decision status

Implemented. Discarded concepts should not be added to production routes. Future refinement should focus on first-viewport vertical economy, keyboard/focus verification and navigation back to the experiment—not additional decoration.

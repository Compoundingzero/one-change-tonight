# Transform.tools audit

Inspected 2026-09-07: directory at 390 × 844 and JSON-to-TypeScript tool at 1440 × 1000. Default input and generated output were observed after processing. Error/reset behavior was not exercised.

## First view and model

The root is a searchable taxonomy of conversions. Choosing a route opens a persistent directory plus a two-pane input/output editor. The JSON-to-TypeScript example supplies harmless sample data and produces a generated interface automatically. Copy is the clear completion action; sign-up is not required.

This dual-pane model makes causality excellent on desktop: input and output share the viewport and update without an explicit submit. Settings are secondary. The product can support many tasks with one repeated shell.

## Responsive behavior

The tested 390 px state did not reflow successfully. The full left directory consumed most of the viewport, while the editor began off-screen to the right and horizontal content was clipped. The first useful action and output were not visible. At 1440 px, the three columns—directory, input, output—were understandable and efficient.

## Trust, accessibility and content

Search and route links were named. Monaco-style editors exposed an accessibility option hint and editable values. Privacy/local processing was not prominent. Route titles are specific but static explanatory content is thin; copying this route-per-phrase pattern into a health-adjacent site would create doorway-page risk.

## Transfer

- Show which observations created which output.
- Use repeatable components and direct route titles for distinct intents.
- Provide immediate feedback without making the user submit each field.

## Do not import

- Do not import the persistent directory, desktop-first dual pane, horizontal overflow or code-editor visuals.
- Do not create dozens of near-duplicate pages for wording variations.
- Do not allow auto-generated output to look like certainty; retain uncertainty and limitations.

# Carbon audit

Inspected 2026-09-07 at 390 × 844 and 1440 × 1000. The default editable sample, theme/language/background/settings controls, preview and export/share controls were observed. Typing, errors and export completion were not exercised.

## First view and model

Carbon opens with a recognizable wordmark, a two-sentence task description and a framed editor/preview already populated with code. The interaction model is editable source embedded in a live visual output, with a compact toolbar. Sign in/up is optional and physically separate.

On desktop, the framed output is the largest visual area and the controls form one row above it. On mobile, controls wrap into a clear grid before the preview; this preserves function but pushes the output down. Export and its dropdown are visually distinct from secondary appearance controls.

## Feedback and control

The sample teaches the tool without an empty state. Theme, language, background, settings, copy/share and export are available immediately. This suits expert creative work but presents more first-step decisions than a sleep-deprived user should face. Undo/reset was not observed.

## Trust, accessibility and content

The code editor, image title, theme and language controls had names in the accessibility tree. Policy links are at the footer; no local-processing promise was observed. Static content is extremely short, which keeps the app central but does not answer a health-adjacent search journey.

## Transfer

- Keep one recognizable output inside a stable frame.
- Distinguish primary completion from optional controls.
- Use a meaningful default state to teach without a tutorial.

## Do not import

- Do not copy Carbon’s black/yellow brand, outlined wordmark, code window or exact toolbar.
- Do not show sharing/export menus or appearance controls before the core result.
- Do not adopt its developer-dark aesthetic or sparse evidence shell.
